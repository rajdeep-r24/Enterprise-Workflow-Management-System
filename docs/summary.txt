# ForgeFlow Project Context (Read Carefully Before Continuing)

## Project Goal

We are building **ForgeFlow**, a Django-based Workflow & HRMS application.

**Current priority is NOT enterprise features.**

Priority is to complete a **working MVP** first.

The MVP must demonstrate:

```
HR creates employee
↓
Employee logs in
↓
Employee submits request
↓
Correct approver receives request
↓
Approver approves/rejects
↓
Employee sees final status
```

Only after this works completely should we improve UI or add advanced features.

# Approver Resolver

Created

```
workflow/services/approver_resolver.py
```

Purpose

DO NOT hardcode

```
employee.manager
```

Instead

```
ApproverResolver.resolve(employee, role_code)
```

Examples

```
MANAGER
↓

employee.manager.user

HR_HEAD
↓

Find employee whose role code = HR_HEAD

IT_HEAD
↓

Find employee whose role code = IT_HEAD
```

This makes workflows configurable.

# MVP Authorization Plan

Do NOT implement enterprise RBAC.

Implement simple role decorator.

Create

```
core/permissions.py
```

Decorator

```
role_required(...)
```

Usage

```
@login_required
@role_required("HR_HEAD","ADMIN")
```

Protect

Employee List

Employee Create

Employee Edit

Employee Deactivate

Workflow Admin

Forms Admin

Approvals

# Coding Rules Going Forward

1. Finish the MVP before adding any enhancements.
2. Every new feature must answer:

   * Who can access it?
   * Can it be bypassed by typing the URL?
3. Keep solutions simple and beginner-friendly.
4. Avoid introducing new layers or abstractions unless they solve an immediate MVP problem.
5. Explain every file change clearly (file name, exact code to replace, and why).
